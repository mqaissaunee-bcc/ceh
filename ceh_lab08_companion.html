Overview — what this lab is really teaching

Once an attacker has a hash — the scrambled form in which systems store passwords — the password itself is only as safe as it is hard to guess. This lab is about that race: build candidate wordlists, then throw them at captured hashes with John the Ripper and Hashcat. It lives in Module 6: System Hacking.

The real lesson isn't "how to crack" — it's why some passwords fall in seconds and others never do. Hash algorithm, salting, length, and predictability decide the outcome long before any tool runs. Understanding that is what lets you give useful password advice.

The environment you're working in

Everything runs on Kali. You create a couple of throwaway Linux accounts, read their hashes out of /etc/shadow, build wordlists, and crack those hashes you own. Nothing here touches a real credential — the point is the mechanics on accounts you made yourself.

Command walkthrough

Read this before you copy anything

The Hashcat and crunch commands in the source PDF use en-dashes (–m, –a, –o) instead of hyphens, which the shell rejects as unknown options. The copy buttons here emit clean hyphens.

Task 1 — Build the targets and the wordlists

1 Create accounts, then read the hashes

root@kali:~# useradd fake3
root@kali:~# useradd fake4
root@kali:~# passwd fake3   # set to 123456
root@kali:~# passwd fake4   # set to password
root@kali:~# cat /etc/shadow

The lab makes two accounts with deliberately weak passwords (123456 and password) so you have something to crack. Linux stores password hashes in /etc/shadow. Each entry's hash starts with an identifier for the algorithm used: $1$ = MD5, $5$ = SHA-256, $6$ = SHA-512. That prefix tells you (and the cracker) what you're up against.

2 Combine passwd + shadow for John

root@kali:~# unshadow /etc/passwd /etc/shadow > hashes.txt
root@kali:~# cat hashes.txt | grep fake* > hashes2.txt

unshadow merges the two files into the single format John expects, then you filter down to just the test accounts you created.

3 Generate candidate passwords with crunch

root@kali:~# crunch 4 8 charset.lst lalpha -o list.txt
root@kali:~# cat owaspwords.txt list.txt > mylist.txt
root@kali:~# cat /usr/share/john/password.lst >> mylist.txt

crunch 4 8 ... lalpha generates every lowercase-alphabetic string from 4 to 8 characters — a brute-force wordlist. The lab then stacks three sources into mylist.txt: the OWASP web-server words, the crunch output, and John's own password list — giving you both predictable passwords and exhaustive short ones. The result is huge (the lab's comes to over 48 million lines), which is why it's slow.

Why this grows fast

Every extra character multiplies the candidate count. That explosion is exactly why length beats complexity for password strength — and why crunch lists stay small on purpose.

Task 2 — Crack with John, then Hashcat

4 John the Ripper

root@kali:~# john --wordlist=/usr/share/john/password.lst hashes2.txt
root@kali:~# john --show hashes2.txt

John auto-detects the hash type and runs a dictionary attack. --show prints what it has already cracked (results are cached in john.pot, so a re-run won't redo work).

5 Prepare the file Hashcat needs

Hashcat wants just the hash, not the user:hash:… format John reads. The lab opens hashes2.txt in a text editor (Mousepad) and, on each line, deletes everything from the first colon onward — leaving the bare hash — then saves it as hashes3.txt. (On the command line, cut -d: -f2 hashes2.txt > hashes3.txt does the same thing.)

6 Hashcat

root@kali:~# hashcat --force -m 1800 -a 0 hashes3.txt mylist.txt -d 1

Hashcat is the GPU-accelerated heavyweight. The flags are the whole skill: -m 1800 is the hash mode (1800 = sha512crypt, the $6$ you saw), -a 0 is the attack mode (0 = straight dictionary), mylist.txt is your wordlist, and -d 1 selects a compute device (add it only if Hashcat errors that it can't reach one). Picking the right -m is the step beginners most often get wrong. While it runs, press s for a status line (hash type, estimated time, speed) and q to quit — it saves progress and resumes where it left off.

The defender's view

This lab is an argument for better password storage

Everything that makes cracking slow is a defensive control you can turn on. The attacker's speed is the defender's checklist, inverted.

  • Store passwords with a slow, salted hash — bcrypt, scrypt, Argon2, or PBKDF2. Salting defeats precomputed (rainbow-table) attacks; slowness caps guesses per second.
  • Require length over complexity — a long passphrase beats a short "complex" password against brute force, as crunch makes obvious.
  • Block known-bad passwords — screen new passwords against breach lists (the rockyou problem) so the easy wins don't exist.
  • Add MFA — a cracked password alone shouldn't grant access.
  • Protect the hashes — if an attacker can't read /etc/shadow or dump a database, there's nothing to crack offline.

CEH v13 exam relevance

Core of the credential-attack content in Module 6: System Hacking. High-yield facts:

  • Hashing vs. encryption — one-way vs. reversible — and why passwords are hashed.
  • Salting and how it defeats rainbow tables.
  • Attack types: dictionary, brute-force, hybrid, rule-based, and rainbow-table.
  • Where hashes live: Linux /etc/shadow, Windows SAM (Lab 22).
  • Tools: John the Ripper and Hashcat, and the role of the hash mode / format.
  • Weak vs. strong algorithms: MD5/LM (weak) vs. bcrypt/Argon2 (strong).

Check yourself

1. A shadow entry begins with $6$. What algorithm is that, and which Hashcat -m mode matches?

SHA-512 crypt (sha512crypt). Hashcat mode -m 1800.

2. What does salting do, and which attack does it specifically defeat?

A salt adds unique random data to each password before hashing, so identical passwords hash differently. It defeats precomputed rainbow-table attacks.

3. Why does a long passphrase beat a short complex password against brute force?

Each added character multiplies the search space far more than swapping a letter for a symbol does, so length grows the keyspace faster than complexity.

4. Hashcat says "no hashes left to crack" the second time you run it. Why?

It already cracked them and cached the results in its potfile. Use --show, or remove the potfile to start over.

Cheat sheet

Prep & John

  • unshadow /etc/passwd /etc/shadow > h.txt
  • john --wordlist=LIST h.txt
  • john --format=NT h.txt
  • john --show h.txt
  • crunch 4 8 charset lalpha -o list.txt

Hashcat modes

  • hashcat -m 0 -a 0 h.txt words — MD5 dict
  • -m 1000 NTLM · -m 1800 sha512crypt
  • -m 3200 bcrypt · -m 22000 WPA
  • -a 3 ?l?l?l?l?d?d — mask brute-force
  • -r rules/best64.rule · --show
