Overview — what this lab is really teaching

Netcat (nc) is the "TCP/IP Swiss army knife" — a tiny tool that reads and writes raw network connections. That simplicity makes it astonishingly flexible: port scanner, chat client, file-transfer tool, and — the reason it's in Module 6: System Hacking — a backdoor. This lab builds up the harmless uses so the backdoor idea is obvious.

The concept to carry away is the difference between a bind shell (netcat listens on the victim, attacker connects in) and a reverse shell (victim connects out to the attacker). Understanding why reverse shells beat firewalls is the whole point — and points straight at the defense.

The environment you're working in

You use two machines in the pod and run nc on both — one as a listener (server) and one as a connector (client). Getting that server/client direction straight is most of the skill here.

Command walkthrough

Read this before you copy anything

The source PDF renders netcat's flags with en-dashes (–l, –zvn, –w) instead of hyphens. The shell rejects them. Use the copy buttons here, which emit clean hyphens.

Task 1 — Port scan

1 A quick connect-scan

root@kali:~# nc -w 1 -zvn 192.168.9.1 1-100

Netcat can scan too: -z is zero-I/O mode (just check if the port answers), -v is verbose, -n skips DNS, -w 1 is a 1-second timeout, and 1-100 is the port range. It's cruder than Nmap but always available.

Task 2 — Make a connection

2 Listener and connector

root@kali:~# nc -l 53
root@kali:~# nc 192.168.0.30 53

One side listens with -l on a port; the other connects to that host and port. Type on either end and it appears on the other — a raw two-way channel. That channel is everything netcat does; the rest is just what you pipe through it.

Task 3 — Transfer a file

3 Pipe a file across

root@kali:~# nc -l 53 > testfile
root@kali:~# nc -w 3 192.168.0.30 53 < testfile

Redirect a file into the connector (< testfile) and out of the listener (> testfile), and netcat moves it across the channel. The same move delivers tools onto a compromised host — which is why file transfer and backdoors are the same skill.

The backdoor idea (concept)

4 Bind vs. reverse shell

If instead of a file you connect netcat to a shell, the channel becomes remote command execution. A bind shell has the victim listen and the attacker connect in; a reverse shell has the victim connect out to a waiting attacker. Reverse wins in the real world because outbound connections are usually allowed while inbound ones are blocked — the same logic as the reverse payload in Lab 21.

A note on the -e flag

The classic backdoor relied on netcat's -e ("execute") option. It was removed from the standard nc precisely because it was so dangerous; where an execute capability exists today (e.g. ncat --exec), EDR watches for exactly this pattern. The defensive point is more useful than the exact syntax: a shell riding a raw socket is a loud, detectable behavior.

Options reference — beyond the lab

FlagDoes
-lListen mode (server side)
-p NSpecify the local port
-z · -v · -nScan (zero-I/O) · verbose · no DNS
-w N · -uTimeout in seconds · UDP instead of TCP
-kKeep listening after a client disconnects
--exec (ncat)Run a program on connect — the backdoor capability

ncat (from the Nmap project) is the modern netcat: it adds TLS, access control, and --exec, and is what you'll usually find on current systems.

The defender's view

A raw channel is easy to make and easy to notice

Netcat backdoors are trivial to set up and, with the right controls, trivial to catch and block.

  • Egress filtering — the single best control. Block unexpected outbound connections and reverse shells have nowhere to call home.
  • EDR / behavior detection — a shell bound to a network socket, or an odd process spawning cmd//bin/sh over the network, is a classic indicator.
  • Application allow-listing — if nc/ncat isn't approved to run, the backdoor never starts.
  • Watch for unexpected listeners — monitor for new listening ports and odd persistent connections.
  • Least privilege + segmentation — limit what a shell can reach even if one opens.

Check yourself

1. In a netcat connection, which side uses -l and which connects to it?

The listener (server) uses -l on a port; the other side connects to that host and port. Start the listener first.

2. Why does a reverse shell usually succeed where a bind shell fails?

A bind shell needs an inbound connection to the victim, which firewalls block. A reverse shell has the victim connect outbound, and outbound is usually allowed — which is why egress filtering is the matching defense.

3. Why was -e removed from standard netcat?

It let netcat execute a program (a shell) on connect — a ready-made backdoor — so it was considered too dangerous to ship by default.

4. What single network control most reliably stops reverse-shell backdoors?

Egress filtering — blocking unexpected outbound connections so the shell can't reach the attacker.

Cheat sheet

Core uses

  • nc -w 1 -zvn HOST 1-100 — scan
  • nc -l 53 — listen
  • nc HOST 53 — connect
  • nc -l 53 > file — receive file
  • nc HOST 53 < file — send file

Concept & defense

  • Bind: victim listens, attacker connects in
  • Reverse: victim connects out (beats firewalls)
  • Modern: ncat --exec (+TLS)
  • Defend: egress filtering, EDR, allow-listing
  • Watch for new listeners / odd outbound
