Overview — what this lab is really teaching

Where Scapy (Lab 02) crafts packets in Python, hping3 does it from the command line — one flag per field. It's the scalpel to Nmap's power tool: you send exactly one packet of your choosing and read exactly what comes back. That precision is what makes it the classic tool for firewall testing (firewalking) and manual probing, and it belongs to Module 3: Scanning Networks.

You'll drive it in three modes — ICMP, traceroute, and TCP — and learn to read a target's state from the flags in its replies.

The environment you're working in

From Kali you probe two targets: the OWASP BWA host at 192.168.68.12 and the pfSense firewall at 192.168.9.1 — probing the firewall is the point, since hping3 shines at inferring filter rules. You'll run tcpdump to watch the exchange on the wire.

Command walkthrough

Read this before you copy anything

Lab PDFs frequently render the option dash as an en-dash (–) instead of a real hyphen (-). Paste –c and the shell says "unknown option." Retype the hyphens, or use the copy buttons here, which emit clean hyphens. Also watch the case: -S sets the SYN flag; -s sets the source port. They are not the same option.

Task 1 — ICMP and traceroute

1 A basic ICMP probe

root@kali:~# hping3 -1 192.168.68.12

-1 selects ICMP mode (the number one, not the letter L). This is a hand-built ping. hping3's default mode is actually TCP, so you ask for ICMP explicitly. Ctrl-C stops it.

2 A specific ICMP type, counted and verbose

root@kali:~# hping3 -c 3 -1 -V -C 13 192.168.68.12

-c 3 sends three packets then stops; -V is verbose; -C 13 sets the ICMP type to 13 — a timestamp request. If echo (ping) is blocked, other ICMP types sometimes still answer, which is itself reconnaissance.

3 Traceroute mode

root@kali:~# hping3 -c 5 -T -1 -V 192.168.68.12

-T turns on traceroute: hping3 increments the TTL and reports each hop. Because you can run traceroute over TCP or ICMP of your choosing, it slips past filters that block the standard UDP traceroute.

Task 2 — TCP probing and firewalk

4 Watch the wire

root@kali:~# tcpdump -i eth0

Leave this running in a second terminal. Now every crafted packet and its reply is visible, so you can confirm what the flags actually did.

5 A single SYN to a port

root@kali:~# hping3 -S -c 1 -s 5151 -p 80 -V 192.168.68.12

One SYN (-S), from source port 5151 (-s), to destination port 80 (-p). Read the reply flags: flags=SA → open, flags=RA → closed, no reply → filtered.

Screenshot for your report

Capture one SYN reply with flags=SA (open) and one with RA (closed), so the difference is on the record.

6 Probe the firewall itself

root@kali:~# hping3 -S -c 1 -s 5151 -p 80 -V 192.168.9.1
root@kali:~# hping3 -S -c 1 -s 5151 -p 22 -V 192.168.9.1

Same probe, now against pfSense on ports 80 and 22. Against port 22 the firewall shows 100% packet loss (closed), while the -8 range scan finds ports 53 and 80 open. Comparing which ports answer, reset, or stay silent lets you infer the firewall's rules — one port at a time. That's firewalking.

7 Scan a range in one command

root@kali:~# hping3 -S -8 20-80 -c 1 -s 5151 -V 192.168.9.1

-8 (scan mode) sweeps the port range 20-80 and summarizes which responded. It's hping3's answer to a quick Nmap scan — slower, but entirely under your control.

The defender's view

What hping3 is used for — and how you counter it

hping3 maps firewalls, spoofs sources, and in flood mode generates denial-of-service traffic. Each capability has a direct defense.

  • Stateful firewalls drop the lone, out-of-sequence packets hping3 sends to probe rules.
  • Anti-spoofing filters (BCP 38 / uRPF) defeat --spoof by discarding packets with impossible source addresses.
  • Rate limiting and SYN protections (SYN cookies) blunt flood attacks.
  • ICMP policy — thoughtfully limit timestamp/other ICMP types so they can't be used to fingerprint or map.
  • IDS/IPS flags the steady trickle of single, oddly-flagged packets that manual probing produces.

CEH v13 exam relevance

Hands-on packet crafting for Module 3: Scanning Networks. High-yield facts:

  • Reading port state from TCP flags: SYN/ACK = open, RST/ACK = closed, no response = filtered.
  • Firewalking — using crafted packets and TTL to infer firewall rules and what's behind them.
  • ICMP types — echo (8/0), timestamp (13/14), and why blocking only echo isn't enough.
  • hping3 as a custom packet crafter for scanning, testing, and DoS; source spoofing with -a.

Check yourself

1. What's the difference between -S and -s in hping3?

-S (capital) sets the TCP SYN flag; -s (lowercase) sets the source port. Different options entirely.

2. Your SYN probe to port 22 returns flags=RA. Is the port open, closed, or filtered?

Closed — RA is RST/ACK, the target actively refusing. SA would be open; silence would suggest filtered.

3. A pasted command returns "unknown option." Most likely reason?

En-dash characters copied from the document instead of real hyphens. Retype the dashes.

4. Why can hping3's traceroute reach hosts that standard traceroute can't?

It can traceroute over TCP (or chosen ICMP types) to ports that firewalls allow, instead of the high-numbered UDP ports classic traceroute uses, which are often blocked.

Cheat sheet

Modes & probes

  • hping3 -1 HOST — ICMP ping
  • hping3 -1 -C 13 HOST — ICMP timestamp
  • hping3 -T -1 HOST — traceroute
  • hping3 -2 -p 53 HOST — UDP probe
  • hping3 -8 1-1000 HOST — scan a range

TCP & reading replies

  • hping3 -S -p 80 -c 1 HOST — one SYN
  • -s 5151 source port · -V verbose
  • Reply SA = open · RA = closed
  • No reply = filtered
  • tcpdump -i eth0 — watch it happen
