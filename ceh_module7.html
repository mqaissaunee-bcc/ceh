🎯 Module Overview

What malware is, and why the definition keeps widening

Malware — malicious software — is any program written to harm, exploit, or gain unauthorized control over a system without the owner's informed consent. That definition sounds simple, but the category has expanded far beyond the viruses of the 1990s into a sprawling ecosystem: ransomware that extorts, infostealers that quietly harvest credentials, rootkits that hide, remote-access trojans that grant control, and increasingly, AI-generated code that rewrites itself to evade detection. This module builds a framework for understanding all of it — not by memorizing a list of named threats, which change monthly, but by learning to classify any piece of malware by what it does and how it behaves, so that a new threat is immediately recognizable as a member of a known family.

Malware connects to nearly every other topic in this course. It is the payload that a phishing email delivers, the tooling an attacker installs after gaining access (as covered in System Hacking), the bot that joins a DDoS botnet, and the ransomware that turns a network breach into a business catastrophe. Understanding malware is therefore understanding the weaponized end of almost every attack.

The landscape in 2026: three shifts that changed everything

The malware of today behaves differently enough from the classical model that the exam and the industry have reorganized around three defining shifts. Keep these in mind throughout the module, because they explain why the old signature-based defenses no longer suffice on their own.

🧬 It changes itself

Roughly 90% of new malware strains are now polymorphic — they alter their own code on every execution, so no two copies share a signature. Signature-based antivirus, which matches known patterns, misses them by design. This is why behavior-based detection has become essential.

👻 It leaves no file

Fileless malware now accounts for the majority of serious incidents. It lives in memory and abuses legitimate built-in tools (PowerShell, WMI) rather than dropping an executable to disk — so file-scanning antivirus has nothing to scan. Detection must watch behavior, not files.

🏭 It's a business

Malware is now a professionalized economy. Ransomware-as-a-Service rents attack kits to affiliates; infostealers feed a marketplace of stolen credentials. The time from initial access to ransomware deployment has collapsed to seconds, because specialized criminal groups hand off to each other.

How this module is organized

The module moves from taxonomy to defense. Malware Types builds the classification framework — the families of malware and what distinguishes each. Analysis covers how professionals safely dissect a malware sample to understand it, through static and dynamic techniques. AI & Emerging Threats examines how generative AI is reshaping both attack and defense. Countermeasures assembles the layered defense that modern malware demands. Tools surveys the analyst's toolkit, and the Labs and Assessment let you apply it all. Throughout, the emphasis is defensive: every offensive capability is paired with how a defender detects and stops it.

Handle with care — and only in isolation. Live malware is dangerous to work with. Real samples are analyzed only inside isolated, monitored sandbox environments with no path to production networks or the internet, precisely because a mistake can spread the infection you are studying. This module teaches the concepts and safe-analysis methodology; never execute unknown or malicious code on a system you cannot afford to lose and fully isolate.

🦠 Malware Types

Two questions that classify any malware

The malware zoo can feel overwhelming, but almost every specimen is classified by answering two independent questions. First: how does it spread and persist? — this distinguishes viruses, worms, and trojans by their propagation mechanism. Second: what is its payload — what does it actually do? — this distinguishes ransomware, spyware, rootkits, and the rest by their purpose. A single real-world threat usually has an answer to both: a worm (propagation) that carries a ransomware payload (purpose), for example. Keeping these two axes separate is the key to classifying anything you encounter.

Propagation: virus, worm, trojan

The classical distinction among the three oldest malware categories is entirely about how they get from one place to another — and it remains a reliable exam favorite.

🦠 Virus — needs a host and a human

A virus attaches itself to a legitimate file or program and cannot spread on its own; it requires a user to run the infected host. When they do, it executes, infects other files, and waits to be carried onward — by a shared file, a USB drive, an email attachment. Its defining trait is dependence: no host file and no human action, no spread.

🐛 Worm — spreads by itself

A worm is self-propagating: it exploits network vulnerabilities to copy itself from machine to machine with no host file and no user action required. This autonomy makes worms explosively fast — historical worms infected the entire vulnerable internet in hours. The IoT botnets from the DDoS module spread worm-style, scanning for and infecting vulnerable devices automatically.

🎭 Trojan — disguised as wanted

A trojan disguises itself as legitimate, desirable software — a game, a utility, a cracked application — so the user installs it willingly. It does not self-replicate; it relies on deception. Trojans are the most common delivery vehicle today because social engineering a user into running something is often easier than exploiting a technical flaw.

Payload: what the malware is for

Once inside, the malware's purpose defines its category. These are the payloads that matter most in 2026, several of which build directly on concepts from the System Hacking module.

💰 Ransomware

Encrypts the victim's files and demands payment for the decryption key. The dominant financial threat: modern operators use double extortion — stealing data before encrypting, then threatening to leak it even if backups exist. Sold as Ransomware-as-a-Service (RaaS), where a core group builds the malware and affiliates deploy it for a cut, industrializing the whole operation.

🕵️ Infostealers & spyware

Silently harvest credentials, session cookies, browser data, and cryptocurrency wallets, then exfiltrate them. The fastest-growing category — families like Lumma, RedLine, and Vidar feed a criminal marketplace where stolen credentials are sold to other attackers, creating a pipeline from a commodity infection to a targeted enterprise breach.

🚪 RATs & backdoors

Remote-access trojans grant the attacker full interactive control — file access, command execution, webcam and keylogging. Backdoors ensure durable re-entry. Covered in depth in System Hacking; here the point is that they are among the most-detected payload types worldwide, often the second stage after an infostealer identifies a valuable target.

👻 Rootkits

Conceal the presence of other malware by subverting the operating system, operating at user or kernel level. Also covered in System Hacking. Their job is stealth and persistence — they are the layer that hides the ransomware's staging or the infostealer's exfiltration from users and security tools.

The modern payloads: wipers, cryptojackers, and loaders

Three more payload types round out the current picture. Wipers are the malicious inverse of ransomware: they destroy data permanently with no recovery mechanism and no ransom — pure sabotage, seen most in geopolitically motivated attacks on critical infrastructure. Cryptojackers hijack a victim's CPU or GPU to mine cryptocurrency for the attacker, quietly stealing computing resources rather than data. Loaders (or droppers) are the delivery specialists — small first-stage programs whose only job is to establish a foothold and then download the real payload, letting attackers separate the break-in from the attack and swap payloads at will. Recognizing a loader matters defensively because catching it early stops whatever it would have fetched next.

Fileless and polymorphic: the evasion revolution

The two techniques that most define modern malware are not payload types but evasion strategies that any payload can adopt — and they are why signature-based antivirus has been dethroned. Fileless malware never writes an executable to disk; it lives in memory and does its work using legitimate, already-installed system tools — PowerShell, WMI, rundll32 — a technique called living off the land. Because there is no malicious file to scan and the tools it abuses are trusted, file-based detection is blind to it, and it now accounts for the majority of serious incidents. Polymorphic malware rewrites its own code on every execution while preserving its behavior, so each copy has a unique signature — defeating the pattern-matching that antivirus relies on. With roughly 90% of new strains polymorphic, the industry has shifted decisively from asking "does this file match a known-bad pattern?" to "is this process behaving maliciously?" — the premise of the EDR and behavioral defenses covered in Countermeasures.

The unifying lesson: propagation and payload tell you what a piece of malware is; fileless and polymorphic techniques tell you why catching it by its fingerprint no longer works. This single insight is the bridge from the taxonomy in this section to the behavior-focused analysis and defense in the rest of the module.

🔬 Malware Analysis

Why analyze malware at all?

When a new threat appears, defenders need to answer urgent questions: What does it do? How does it spread? What has it touched on our network? How do we detect and remove it? Malware analysis is the discipline of safely dissecting a sample to answer those questions. The output feeds everything downstream — detection signatures, incident-response scoping, and threat intelligence. It is a specialized skill, but the framework is understandable and appears on the exam: analysis proceeds along two complementary approaches, static and dynamic, usually combined.

The cardinal rule: isolation

Before any technique, one principle governs all malware analysis: it happens in isolation. Analysts work inside a sandbox — a virtual machine or dedicated environment deliberately cut off from production networks and often from the internet — so that if the sample executes and tries to spread, encrypt, or phone home, it does so harmlessly in a controlled cage. The sandbox is monitored and snapshotted, so the analyst can run the malware, observe everything it does, then instantly roll back to a clean state. Skipping isolation is how analysts become patient zero. Sophisticated malware even tries to detect that it is being analyzed — checking for virtual-machine artifacts or analysis tools and lying dormant if it finds them — which is an ongoing cat-and-mouse within the discipline.

Static analysis: examining without running

Static analysis studies the malware without executing it — inspecting the file itself for clues. This is safe (the code never runs) and fast, and it often reveals a great deal. Analysts examine the file's structure and metadata, extract readable strings (embedded text like URLs, IP addresses, ransom notes, or command names that hint at behavior), compute file hashes to check against known-malware databases, and, at the deepest level, disassemble the code to read its logic directly. Static analysis answers "what is this built to do?" without the risk of letting it do it.

Its limitation is that modern malware fights back. Packing and encryption compress or scramble the real code so that static inspection sees only an unpacking stub, not the payload — the malware only reveals its true form when it runs. This is exactly where dynamic analysis becomes necessary.

Dynamic analysis: watching it run

Dynamic analysis executes the malware in the sandbox and observes its behavior. This sidesteps packing entirely — however the code is obfuscated on disk, it must reveal its true actions when it runs. Analysts monitor what the sample does: which files it creates or encrypts, which registry keys it modifies for persistence, which processes it spawns, and — critically — what network connections it makes, which reveal its command-and-control servers and exfiltration destinations. Watching a ransomware sample begin encrypting files, or an infostealer reach out to a C2 address, tells you in minutes what static analysis might never extract from packed code.

The two approaches are complementary, not competing. Static analysis maps the terrain safely; dynamic analysis confirms what the malware actually does. A typical workflow runs static first to understand structure and flag danger, then dynamic to observe behavior, then often returns to static disassembly to understand how a specific observed behavior is implemented.

Why behavioral analysis is the future

The shift toward fileless and polymorphic malware, described earlier, has made dynamic and behavioral analysis increasingly central. When 90% of strains have unique signatures and many never touch disk, static signature-matching cannot keep up — but behavior is much harder for malware to disguise. A process that spawns PowerShell, reads browser credential stores, and opens an outbound connection to an unfamiliar host is suspicious regardless of what its file looks like or whether a file exists at all. This is the principle behind modern EDR (Endpoint Detection and Response) and behavioral detection: watch what programs do, not just what they are. The analysis techniques in this section are the manual, deep-dive version of what EDR automates at scale across an organization.

🤖 AI & Emerging Threats

How generative AI is reshaping malware

The most significant change in the malware landscape since this course was first written is the arrival of generative AI on both sides of the fight. Attackers now use large language models to write and mutate malicious code, craft convincing phishing lures, and generate polymorphic variants automatically. Defenders use the same class of technology to detect anomalies that no human-written rule could anticipate. This section examines that arms race honestly — neither dismissing AI as hype nor treating it as magic — because understanding it is now essential to understanding the threat.

AI as an attacker's tool

Generative AI lowers the skill and time required to produce effective malware, which is its most immediate impact. Several concrete uses have moved from theory to observed reality:

🧬 Automated polymorphism

AI can rewrite a piece of malware's code endlessly while preserving its function, generating a unique variant for every target. This industrializes the polymorphism that already defeats signature detection — and observed cases (such as the Slopoly incident) show LLM-generated malware appearing in live ransomware operations, not just research demos.

🎣 Hyper-convincing phishing

AI-generated phishing is now the primary delivery vector for most malware, because AI writes fluent, personalized, error-free lures at scale — raising click-through rates substantially. Combined with deepfake audio and video, it enables impersonation attacks that deceive even trained users.

⚡ Faster development

Tasks that once required an expert — writing an exploit, obfuscating a payload, building C2 logic — can be accelerated with AI assistance, collapsing the time and expertise barrier that once limited who could produce capable malware.

🎯 Adaptive, real-time evasion

The emerging frontier is malware that uses AI to adapt its behavior during an intrusion — probing defenses and changing tactics in real time to blend into normal activity, rather than following a fixed script an analyst could predict.

A new attack surface: the AI systems themselves

Beyond being a tool, AI systems are becoming targets, creating attack vectors that did not exist a few years ago. Prompt injection manipulates an LLM-driven tool into executing unintended actions — exposing data, generating malicious commands, or bypassing its own guardrails — and when an application automatically trusts an AI's output, prompt injection becomes a genuine malware delivery and execution vector. As organizations embed AI assistants into workflows with real permissions, the AI itself becomes something an attacker tries to subvert. This is an area the traditional malware taxonomy is still adapting to, and one worth watching closely.

AI as a defender's tool

The same technology is a powerful defensive asset, and it has to be, given what it enables on offense. Because AI-driven and polymorphic malware defeats static signatures, defenders lean on machine learning to model normal behavior across far more dimensions than any hand-written rule set could — flagging the subtle deviations that betray an intrusion even when every individual action looks legitimate. Modern EDR and network-detection systems use ML to correlate signals across endpoints, identity, and network traffic, catching the "blends into normal traffic" attacks that are specifically designed to evade rule-based detection. The defensive principle emerging for 2026 is correlation: when malware is engineered so that each action appears benign in isolation, the only reliable signal is the relationship between actions across identity, network, and endpoint — a job suited to machine learning at scale.

Keeping perspective

It is worth ending on a balanced note. AI has genuinely shifted the landscape — faster, more evasive, more accessible attacks are real, not hypothetical. But the fundamentals of defense remain what they have always been: least privilege, patching, network segmentation, good backups, user awareness, and behavioral monitoring. AI raises the volume and sophistication of attacks and lowers the barrier to launching them, but it does not repeal the underlying principles. The defender's job is not to find a magic AI countermeasure, but to apply proven fundamentals rigorously while adopting AI-enhanced detection to keep pace with AI-enhanced attacks.

🛡️ Countermeasures

Why defense must be layered

No single control stops modern malware, because modern malware is specifically engineered to defeat single controls. Signature antivirus misses polymorphic code; file scanning misses fileless attacks; a firewall misses malware a user invites in through a trojan. Effective defense is therefore defense in depth — overlapping layers arranged so that what one layer misses, the next catches. Just as importantly, the layers span the whole attack lifecycle: preventing infection, detecting what gets through, containing what activates, and recovering from what succeeds. A useful way to organize the countermeasures is by which phase of that lifecycle they address.

Prevention: stopping infection

The first layer aims to keep malware out entirely. Its most valuable controls are the unglamorous fundamentals that repeatedly prove decisive:

  • Patching and vulnerability management. Worms and exploit-based malware spread through unpatched flaws; timely patching removes the doorways they use. With new exploitable vulnerabilities appearing constantly, this is a continuous discipline, not a periodic chore.
  • Least privilege. Malware inherits the privileges of whatever runs it. A user who cannot install software or write to system directories sharply limits what malware executing as them can accomplish — one of the highest-leverage controls available.
  • Email and web filtering. Since AI-generated phishing is now the primary delivery vector, filtering malicious attachments and links at the gateway blocks a large fraction of malware before it reaches a user.
  • Application allow-listing. Permitting only approved programs to run stops unknown executables outright — a strong defense against novel and polymorphic malware whose signatures are unknown.
  • User awareness. Because trojans and phishing depend on tricking a person, trained users who hesitate before enabling a macro or running an emailed "invoice" are a real control, not a soft one.

Detection: catching what gets through

Prevention is never perfect, so the second layer assumes some malware gets in and focuses on finding it fast — because the time between infection and damage is now measured in minutes. This is where the shift from signatures to behavior, emphasized throughout the module, becomes concrete.

Signature-based antivirus

Still useful as a cheap first filter that catches the enormous volume of known, commodity malware. But because ~90% of new strains are polymorphic and fileless attacks leave no file, it can no longer be the primary defense — it is a floor, not a ceiling.

EDR & behavioral detection

The modern centerpiece. Endpoint Detection and Response watches process behavior — what programs spawn, what they touch, what they connect to — and flags malicious activity regardless of whether a file matches a known pattern. This is the only reliable answer to polymorphic and fileless malware, and it includes the memory analysis needed to catch threats that never touch disk.

The frontier, as noted in the AI section, is correlation across signals — combining endpoint behavior with identity and network telemetry so that attacks designed to look benign in isolation are caught by the relationships between their actions. When each individual step of an intrusion looks legitimate, only the pattern across steps reveals it.

Containment and recovery: limiting and reversing damage

The final layers assume malware not only got in but activated, and focus on limiting the blast radius and recovering. Network segmentation divides the network so that malware which compromises one segment cannot freely reach the rest — the single most effective control against ransomware spreading laterally across an organization. Isolation and response capabilities (a core EDR feature) let defenders quarantine an infected host the moment it is detected, cutting off spread and C2 communication.

And when all else fails, reliable, tested, offline backups are the ultimate answer to ransomware — they turn a catastrophic extortion event into an inconvenient restore. The critical qualifiers are offline (so the ransomware cannot encrypt the backups too) and tested (a backup you have never restored from is a hope, not a plan). The rise of double-extortion ransomware, which leaks stolen data even when backups defeat the encryption, means backups must be paired with the prevention and detection layers above — they solve the availability problem but not the confidentiality one.

The strategy in one sentence

Prevent what you can with fundamentals, detect what gets through with behavioral monitoring, contain what activates with segmentation and isolation, and recover what succeeds with tested offline backups — no layer sufficient alone, all of them together resilient. That layered posture, applied rigorously, is what modern malware demands and what this module has built toward.

🛠️ Analysis Tools

The analyst's toolkit, organized by task

Malware analysis tools map directly onto the static and dynamic approaches from the Analysis section. Rather than memorize a flat list, group each tool by the job it does — safe inspection, behavioral observation, or deep reverse engineering — and the toolkit becomes a coherent workflow. The tools below are the ones a working analyst reaches for, and the ones the exam expects you to recognize.

Static analysis tools

Strings & PEStudio

First-pass triage. strings extracts readable text from a binary — URLs, IP addresses, ransom notes, command names — that hint at behavior. PEStudio inspects a Windows executable's structure, imports, and metadata for red flags, all without running the file.

Hashing & VirusTotal

Computing a sample's hash and checking it against threat-intelligence databases like VirusTotal instantly reveals whether it is already-known malware and what dozens of engines think of it — the fastest possible identification for commodity threats.

Ghidra & IDA

Disassemblers and decompilers for deep reverse engineering — translating machine code back into readable logic to understand exactly how a sample works. Ghidra (free, from the NSA) and IDA Pro are the industry standards, used when triage isn't enough and you need to understand the code line by line.

Unpacking tools

Because packing hides the real code from static inspection, analysts use unpackers and debuggers to reveal the payload beneath the packer stub — the prerequisite for meaningful static analysis of protected malware.

Dynamic analysis tools

Automated sandboxes

Systems like Cuckoo Sandbox and commercial equivalents run a sample in an instrumented VM and automatically report everything it does — files touched, registry changes, processes spawned, network connections made. They turn dynamic analysis into a largely push-button process and are the workhorse of high-volume malware triage.

Process & system monitors

Tools like Process Monitor and Process Explorer (Sysinternals) show in real time what a running sample does to the system — every file, registry, and process operation — letting an analyst watch the malware's behavior unfold live inside the sandbox.

Network analysis

Wireshark and similar tools (from the Sniffing module) capture the malware's network traffic, revealing its command-and-control servers and exfiltration destinations — often the most valuable intelligence a sample yields, since it exposes the attacker's infrastructure.

Debuggers

x64dbg and OllyDbg let an analyst step through a sample's execution instruction by instruction, pausing and inspecting memory — bridging static and dynamic analysis for the hardest cases, including malware that tries to detect and evade sandboxes.

From tools to defense at scale

The tools above are for analyzing individual samples — the manual, deep-dive craft. The organizational equivalent, operating continuously across every endpoint, is the EDR platform discussed in Countermeasures: it applies the same behavioral-observation principles automatically, at scale, without an analyst examining each file. Understanding the manual tools makes you a better operator of the automated ones, because you understand what "suspicious behavior" actually looks like at the level EDR is watching. The analyst's microscope and the enterprise's EDR are two views of the same discipline: judging software by what it does.
