Net 101 OSI Model

A seven-layer reference model that splits networking into independent jobs: Physical, Data Link, Network, Transport, Session, Presentation, Application (layers 1–7).

The OSI model is a mental filing system for networking. Each layer does one job and hands its result to the layer above or below. Layer 1 (Physical) is cables and radio; Layer 2 (Data Link) moves frames between devices on the same local network using MAC addresses; Layer 3 (Network) moves packets between networks using IP addresses; Layer 4 (Transport) handles end-to-end delivery with TCP or UDP and port numbers; Layers 5–7 handle sessions, data formatting, and the application itself.

In practice the TCP/IP model (four layers) is what the Internet actually runs on, but CEH and most tools still describe attacks by OSI layer because it tells you *where* an attack operates.

Why it matters for CEH: Attacks are categorized by layer. ARP spoofing is Layer 2, IP spoofing and ICMP tricks are Layer 3, SYN floods and port scans are Layer 4, and SQL injection or XSS are Layer 7. Knowing the layer tells you which defense applies.
Quick check

A switch forwards traffic using MAC addresses, and a router forwards using IP addresses. Which OSI layer does each operate at?

Answer: Switch = Layer 2 (Data Link). Router = Layer 3 (Network).

Net 101 TCP/IP Model

The four-layer model the Internet really uses: Link, Internet, Transport, Application — a simplified cousin of OSI.

The TCP/IP model collapses OSI's seven layers into four. The Link layer covers OSI 1–2 (Ethernet, Wi-Fi, MAC addresses). The Internet layer is OSI 3 (IP, ICMP, routing). The Transport layer is OSI 4 (TCP and UDP). The Application layer covers OSI 5–7 (HTTP, DNS, SSH, everything an app speaks).

When a tool or exam says 'the transport layer,' it means the same thing in both models — TCP/UDP and ports. The two models are just different-resolution maps of the same territory.

Why it matters for CEH: Most scanning and sniffing tools let you operate at a chosen layer. Understanding the stack tells you what a captured packet contains at each level and what a scanner is actually probing.
Quick check

A packet capture shows an Ethernet header, then an IP header, then a TCP header, then HTTP data. Which TCP/IP layer produced each header?

Answer: Ethernet = Link, IP = Internet, TCP = Transport, HTTP = Application.

Net 101 Encapsulation

As data moves down the stack, each layer wraps it in its own header (and sometimes trailer), like nested envelopes.

When your browser sends a request, the Application layer produces the data, the Transport layer wraps it in a TCP segment (adding ports and sequence numbers), the Internet layer wraps that in an IP packet (adding source/destination IP), and the Link layer wraps that in an Ethernet frame (adding MAC addresses). Each wrapper is a header. The receiving side unwraps them in reverse — decapsulation.

This is why a single piece of data on the wire carries several addresses at once: MAC (who's the next hop), IP (who's the final destination), and port (which service).

Why it matters for CEH: Packet crafting and sniffing both depend on this. When you read a capture in Wireshark, you are looking at the nested headers encapsulation produced. Spoofing an attack means forging a field in one of these layers.
Quick check

Which address does encapsulation add at Layer 2, and does it change at every hop or stay the same end-to-end?

Answer: The MAC address is added at Layer 2 and changes at every hop. The IP address stays the same end-to-end.

Net 101 TCP Three-Way Handshake

How two hosts open a reliable TCP connection: SYN → SYN/ACK → ACK.

TCP connections start with a three-step negotiation. The client sends a SYN (synchronize) with an initial sequence number. The server replies SYN/ACK, acknowledging the client's number and sending its own. The client replies ACK. Now both sides agree on sequence numbers and the connection is 'established.' A FIN or RST tears it down.

The sequence numbers chosen here matter: they're how TCP keeps bytes in order and how it rejects packets that don't belong.

Why it matters for CEH: A full-connect scan completes the whole handshake (noisy, logged). A SYN / 'half-open' scan sends SYN, reads the reply, then never sends the final ACK (stealthier). A SYN flood abuses step 1 to exhaust a server. Session hijacking abuses the sequence numbers set up here.
Quick check

In a SYN scan, which of the three steps does the scanner deliberately skip, and why?

Answer: It skips the final ACK, so the connection never fully opens — making the scan quieter and less likely to be logged as a real connection.

Net 101 TCP Flags

Control bits in the TCP header — SYN, ACK, FIN, RST, PSH, URG — that signal connection state.

Each TCP segment has a set of 1-bit flags. SYN opens a connection, ACK acknowledges received data, FIN closes gracefully, RST aborts abruptly, PSH says 'deliver this now,' URG marks urgent data. A normal connection is a predictable sequence of these flags.

Scanners exploit the rules for how a host *must* respond to unusual flag combinations. For example, a closed port must answer certain probes with RST, while an open port may stay silent.

Why it matters for CEH: FIN, NULL, and Xmas scans send odd flag combinations to infer port state from the response (or lack of one). An RST in reply usually means 'port closed.' These scans can slip past simple filters that only watch for SYN.
Quick check

A scanner sends a packet with no flags set (a NULL scan) to a port and gets no response. On most systems, what does that suggest?

Answer: No response suggests the port is open (or filtered). A closed port would typically reply with RST.

Net 101 TCP vs. UDP

TCP is connection-oriented and reliable (handshake, ordering, retransmission). UDP is connectionless and fast (fire-and-forget).

TCP sets up a connection, numbers every byte, acknowledges receipt, and retransmits what's lost — good for web, email, SSH. UDP just sends datagrams with no handshake and no guarantee — good for DNS queries, DHCP, VoIP, and streaming where speed beats perfection.

The difference shapes how each is scanned: TCP gives you clear handshake signals, while UDP's silence is ambiguous (no reply could mean open *or* filtered).

Why it matters for CEH: UDP scanning is slower and less reliable precisely because UDP doesn't answer predictably. Many high-value services (DNS 53, SNMP 161, DHCP 67/68) run over UDP, so you can't skip it.
Quick check

Why is scanning a UDP port harder to interpret than scanning a TCP port?

Answer: UDP has no handshake. An open UDP port often sends nothing back, which looks the same as a filtered port, so results are ambiguous.

Net 101 Ports & Services

A 16-bit number (0–65535) that identifies which service a packet is for. Well-known services use fixed ports.

An IP address gets you to a host; a port number gets you to the right service on that host. Ports 0–1023 are 'well-known' (HTTP 80, HTTPS 443, SSH 22, DNS 53, SMB 445). Ports above that are registered or ephemeral (temporary client-side ports). A service 'listening' on a port is waiting for connections there.

Port state is the core output of scanning: open (a service is listening), closed (nothing listening but host reachable), or filtered (a firewall is blocking the probe).

Why it matters for CEH: The whole point of port scanning is mapping which ports are open and what's behind them. An open port is a potential door; the service and version behind it tell you what exploits might apply.
Quick check

A scan reports port 445 open. What common service is that, and why would an attacker care?

Answer: Port 445 is SMB (Windows file sharing). It's a frequent target for enumeration and well-known exploits, so an open 445 is a strong lead.

Net 101 IP Addressing

The numeric address that identifies a host on a network — IPv4 (e.g. 192.168.1.10) or IPv6. Can be public or private.

An IPv4 address is four numbers 0–255 (32 bits total). Some ranges are private (10.x, 172.16–31.x, 192.168.x) and only valid inside a local network; the rest are public and routable on the Internet. IPv6 is the much larger successor, written in hex groups.

Private addresses reach the Internet through NAT, which is why many hosts can share one public IP.

Why it matters for CEH: Target selection starts with IP ranges. Recognizing private vs. public addressing tells you whether you're looking at an internal host or an Internet-facing one, which changes the whole attack path.
Quick check

Is 192.168.4.20 a public or private address, and can a host on the Internet route to it directly?

Answer: Private. The Internet can't route to it directly — it's only reachable inside the local network or via NAT/port forwarding.

Net 101 Subnetting & CIDR

Dividing an IP range into smaller networks. CIDR notation (e.g. /24) says how many bits are the network portion.

A subnet mask splits an IP address into a network part and a host part. CIDR notation writes this as a slash number: /24 means the first 24 bits are the network, leaving 8 bits (256 addresses) for hosts. So 192.168.1.0/24 covers 192.168.1.0 through 192.168.1.255.

Smaller numbers after the slash mean bigger networks: /16 is 65,536 addresses, /24 is 256, /30 is 4.

Why it matters for CEH: When you scan '192.168.1.0/24' you're telling the scanner to sweep all 256 addresses in that subnet. Reading CIDR correctly is how you aim a scan at the right scope — too broad is noisy, too narrow misses hosts.
Quick check

How many host addresses does a /24 network contain, and how many does a /16 contain?

Answer: A /24 contains 256 addresses (254 usable); a /16 contains 65,536.

Net 101 MAC Address

A 48-bit hardware address burned into a network interface, used for delivery within a local network (Layer 2).

Every network interface has a MAC address (e.g. 00:1A:2B:3C:4D:5E). It's how devices on the same local segment find each other. Unlike an IP address, which is logical and changes as you move between networks, a MAC is tied to the hardware — though it can be spoofed in software.

The first half identifies the manufacturer (the OUI), which can leak what kind of device you're looking at.

Why it matters for CEH: MAC spoofing defeats MAC-based access control and hides a device's identity. ARP attacks work by lying about which MAC owns which IP. On Wi-Fi, MAC addresses are visible even when traffic is encrypted.
Quick check

You change your interface's MAC to match an authorized device. What kind of access control does this defeat, and does it change your IP address?

Answer: It defeats MAC filtering (common on Wi-Fi). It does not change your IP — MAC and IP are separate addresses at different layers.

Net 101 ARP (Address Resolution Protocol)

Maps an IP address to a MAC address on the local network so frames can actually be delivered.

To send a packet to 192.168.1.50 on your LAN, a host needs that device's MAC address. ARP is the question: 'Who has 192.168.1.50? Tell me your MAC.' The owner replies, and the answer is cached in the ARP table. The catch: ARP has no authentication — any device can answer, truthfully or not.

This trust-by-default design is the root of a whole family of local attacks.

Why it matters for CEH: ARP spoofing/poisoning sends forged replies so the victim's traffic is sent to the attacker instead of the gateway — the basis for man-in-the-middle attacks and local sniffing on switched networks.
Quick check

Why can an attacker intercept traffic with ARP spoofing even on a switched network, where the switch normally isolates traffic?

Answer: Because ARP has no authentication. The attacker poisons the victim's ARP cache so the victim sends frames to the attacker's MAC, bypassing the switch's normal isolation.

Net 101 DNS (Domain Name System)

The Internet's directory — translates names like example.com into IP addresses.

DNS turns human-friendly names into IP addresses. A resolver asks a chain of servers until it finds the authoritative answer, then caches it. Record types carry different info: A (IPv4), AAAA (IPv6), MX (mail servers), NS (name servers), TXT (arbitrary text), CNAME (aliases).

Because almost everything starts with a DNS lookup, DNS data is a goldmine for mapping a target — and DNS traffic is a convenient channel for attackers to hide in.

Why it matters for CEH: DNS enumeration (and zone transfers, when misconfigured) reveals subdomains, mail servers, and infrastructure. DNS is also abused for tunneling/exfiltration and for spoofing victims to malicious IPs.
Quick check

During reconnaissance, why are a target's MX and NS records useful even though you're not attacking email yet?

Answer: They reveal infrastructure — mail servers and name servers — expanding your map of the target's systems and possible entry points.

Net 101 DHCP

Automatically hands out IP addresses and network settings (gateway, DNS) to devices joining a network.

When a device joins a network, it broadcasts asking for configuration. A DHCP server offers an IP address, subnet mask, default gateway, and DNS servers, on a lease. The exchange is Discover → Offer → Request → Acknowledge (DORA). Like ARP, classic DHCP has no authentication.

Because DHCP tells a client who its gateway and DNS are, controlling DHCP means controlling where a victim's traffic goes.

Why it matters for CEH: A rogue DHCP server can hand victims a malicious gateway or DNS, steering their traffic through the attacker. DHCP starvation exhausts the pool so the rogue server wins.
Quick check

If an attacker's rogue DHCP server hands a victim a malicious DNS server, what can the attacker now do?

Answer: Redirect the victim's name lookups — sending them to attacker-controlled IPs for sites they think are legitimate.

Net 101 ICMP / Ping

A control-message protocol used for diagnostics — ping (echo) and traceroute ride on it.

ICMP carries network control and error messages rather than user data. 'Ping' sends an ICMP echo request and waits for an echo reply to check if a host is alive and measure latency. Traceroute abuses TTL expiry messages to map the hops between you and a target.

Many networks block or rate-limit ICMP, so 'no ping reply' doesn't prove a host is down.

Why it matters for CEH: Host discovery often starts with ICMP sweeps. But because ICMP is frequently filtered, scanners fall back to TCP/UDP probes to find live hosts. ICMP is also abused for tunneling and some DoS techniques.
Quick check

A ping to a server times out. Can you conclude the server is offline? Why or why not?

Answer: No. The host or a firewall may simply be dropping ICMP. You'd confirm with TCP/UDP probes to known ports.

Net 101 HTTP / HTTPS

The protocol of the web. HTTP is plaintext; HTTPS is HTTP wrapped in TLS encryption.

HTTP is a request/response protocol: a client sends a method (GET, POST, etc.) to a URL with headers, and the server replies with a status code (200 OK, 404 Not Found, 500 error) and a body. HTTPS is the same thing carried inside a TLS-encrypted channel, so eavesdroppers see only ciphertext.

Headers and status codes carry a lot of signal — server software, cookies, redirects, caching — much of it useful to an attacker.

Why it matters for CEH: Web attacks (injection, XSS, directory traversal) are crafted HTTP requests. Response headers and status codes fingerprint the server and reveal misconfigurations. Over plain HTTP, credentials and cookies travel in the clear.
Quick check

Why does capturing traffic on plain HTTP expose a login, while HTTPS does not?

Answer: HTTP sends data in plaintext, so a sniffer reads the credentials directly. HTTPS encrypts the whole exchange with TLS, so a sniffer sees only ciphertext.

Net 101 TLS / SSL

The encryption layer that secures traffic (HTTPS, secure email, VPNs). SSL is its obsolete predecessor.

TLS provides confidentiality (encryption), integrity (tamper detection), and authentication (certificates proving you're talking to the real server). A TLS handshake negotiates a cipher, validates the server's certificate, and establishes session keys. 'SSL' is the old name; the modern protocol is TLS 1.2/1.3.

A certificate chains back to a trusted Certificate Authority — which is exactly what a man-in-the-middle must defeat or forge.

Why it matters for CEH: Weak ciphers, expired or self-signed certs, and old SSL/TLS versions are common findings. SSL stripping and rogue certificates are how attackers pierce HTTPS. CEH expects you to recognize these weaknesses.
Quick check

What three guarantees does a correctly configured TLS connection provide?

Answer: Confidentiality (encryption), integrity (tamper detection), and authentication (the server's identity via its certificate).

Net 101 Switching vs. Routing

Switches move frames within a local network (Layer 2, MAC). Routers move packets between networks (Layer 3, IP).

A switch connects devices on the same local network and forwards frames by MAC address, learning which device is on which port. A router connects different networks and forwards packets by IP address, choosing the next network hop. Your 'default gateway' is the router that leads off your local network.

The boundary matters for attacks: Layer 2 attacks (ARP, MAC) stay within a switched segment; crossing into other networks is a Layer 3 (routing) problem.

Why it matters for CEH: Sniffing on a switched network requires defeating the switch (ARP poisoning, MAC flooding) because the switch won't just hand you other devices' traffic. Knowing where the Layer 2/3 boundary sits tells you how far an attack can reach.
Quick check

Why is passive sniffing easy on an old hub but hard on a modern switch?

Answer: A hub broadcasts every frame to all ports, so you see everything. A switch forwards frames only to the intended port, so you must actively subvert it to capture others' traffic.

Net 101 NAT (Network Address Translation)

Lets many private hosts share one public IP by rewriting addresses at the router.

NAT rewrites the source address of outbound packets so internal private IPs (like 192.168.x) appear to come from the router's single public IP, and it maps replies back to the right internal host using port numbers. This conserves public IPs and incidentally hides internal hosts.

Port forwarding is the manual exception: the router sends a chosen public port to a specific internal host, deliberately exposing a service.

Why it matters for CEH: NAT hides internal addressing from outside scans — you see the public edge, not the hosts behind it. Port-forwarding rules are exactly the deliberately exposed services worth probing.
Quick check

Why can't you directly scan an internal host behind NAT from the Internet unless a port-forward exists?

Answer: NAT only maps replies to connections an internal host started, or to explicitly forwarded ports. Unsolicited inbound traffic has no mapping, so it can't reach internal hosts.

Net 101 TTL & Fragmentation

TTL limits how many hops a packet can travel; fragmentation splits a packet too big for a link.

Every IP packet has a Time To Live (TTL) that drops by one at each router; at zero the packet is discarded (this is what traceroute exploits). Fragmentation splits a packet that exceeds a link's maximum size into pieces that are reassembled at the destination.

Both fields are predictable enough to fingerprint systems — and malleable enough to abuse.

Why it matters for CEH: Default TTL values differ by OS, so TTL helps fingerprint a target. Fragmentation is an evasion technique: splitting an attack across fragments can slip past IDS/firewalls that don't reassemble packets the way the target does.
Quick check

How can an attacker use packet fragmentation to evade an IDS?

Answer: By splitting a malicious payload across fragments so the IDS, if it reassembles differently than the target host, fails to recognize the attack while the host still reassembles and executes it.

Net 101 CAM / MAC Table

The switch's memory of which MAC address lives on which port. Overflowing it can turn a switch into a hub.

A switch builds a table mapping MAC addresses to physical ports so it can forward frames only where they belong. This table (the CAM table) is finite. If it fills up, many switches 'fail open' and start flooding all frames to every port — behaving like a hub.

That failure mode is the whole point of a MAC flooding attack.

Why it matters for CEH: MAC flooding (e.g. with macof) overflows the CAM table so the switch floods traffic, letting an attacker passively sniff a switched network. It's the brute-force cousin of ARP poisoning.
Quick check

What happens to a switch's forwarding behavior when its CAM table is overflowed, and why does that help an attacker?

Answer: It fails open and floods frames to all ports like a hub, so the attacker can now passively capture traffic meant for other devices.

Net 101 Wi-Fi (802.11)

The family of wireless LAN standards. Networks are named by SSID; access points are identified by BSSID (a MAC).

802.11 is the set of standards behind Wi-Fi. An access point advertises its network name (SSID) in beacon frames; its radio has a hardware address called the BSSID. Clients associate with an AP to join. Because the medium is radio, anyone in range can hear the frames — even if the payload is encrypted.

Management frames (beacons, authentication, deauthentication) were historically unprotected, which enables several attacks.

Why it matters for CEH: Wireless attacks exploit the open medium: capturing handshakes for offline cracking, deauth attacks to force reconnection, and evil-twin APs that imitate a real SSID. Monitor mode lets a card capture all nearby frames.
Quick check

Why can an attacker capture Wi-Fi frames without connecting to the network, and what stops them from reading the contents?

Answer: Radio is a shared medium — frames are in the air for anyone in range to capture. Encryption (WPA2/WPA3) is what keeps the payload unreadable without the key.

Net 101 Promiscuous / Monitor Mode

Interface modes that capture all traffic the card can hear, not just traffic addressed to it.

Normally a network card ignores frames not addressed to its own MAC. Promiscuous mode tells a wired card to hand every frame it receives up to the OS — essential for sniffing. On Wi-Fi, monitor mode goes further, capturing raw 802.11 frames from the air without associating to any network.

Without these modes, a sniffer only sees its own traffic, which defeats the purpose.

Why it matters for CEH: Sniffers like Wireshark and tcpdump rely on promiscuous mode; wireless capture and handshake collection rely on monitor mode. Knowing the difference explains why some captures see 'everything' and others see almost nothing.
Quick check

You run Wireshark but only see your own machine's traffic on a switched network. Name two reasons.

Answer: The interface isn't in promiscuous mode, and/or the switch isn't flooding traffic to your port (you'd need ARP poisoning or MAC flooding to see others' traffic).

Net 101 Proxy

An intermediary that forwards traffic on your behalf — forward proxies hide the client, reverse proxies front the server.

A forward proxy sits between a client and the Internet, making requests on the client's behalf (hiding or changing the client's apparent origin). A reverse proxy sits in front of servers, receiving requests and passing them to backends (load balancing, caching, TLS termination, WAF).

Intercepting proxies (like Burp Suite) are a special case: they sit between browser and server so you can read and modify every request.

Why it matters for CEH: An intercepting proxy is the core web-testing tool — it lets you tamper with HTTP requests. Attackers also chain proxies to obscure their origin, and reverse proxies/WAFs are defenses you must recognize and sometimes evade.
Quick check

What does an intercepting proxy like Burp Suite let a tester do that a normal browser cannot?

Answer: Pause, read, and modify each HTTP request and response before it's sent or rendered — enabling manual injection and tampering tests.

Net 101 VPN / Tunneling

An encrypted tunnel that carries traffic across an untrusted network as if you were on a trusted one.

A VPN wraps your traffic in an encrypted tunnel to a remote endpoint, so intermediaries see only the encrypted outer packets, not the inner traffic. More generally, 'tunneling' means carrying one protocol inside another — which can be legitimate (secure remote access) or sneaky (smuggling data out inside DNS or HTTPS).

The same mechanism that protects privacy can also hide an attacker's activity from network defenders.

Why it matters for CEH: VPNs defeat passive sniffing of the tunneled traffic. Attackers use tunneling (DNS, ICMP, HTTPS) to exfiltrate data and bypass egress filtering, so recognizing tunnel signatures is a defensive skill CEH tests.
Quick check

Why does data exfiltration over a DNS tunnel often slip past firewalls?

Answer: DNS is almost always allowed outbound for normal name resolution, so a tunnel disguised as DNS queries blends into traffic firewalls routinely permit.

Net 101 VLAN (Virtual LAN)

A way to split one physical switch into several isolated logical networks, so traffic in one VLAN can't normally reach another.

A VLAN lets a single switch act like several separate switches. Ports are tagged with a VLAN ID, and the switch keeps each VLAN's traffic isolated — devices in VLAN 10 don't see VLAN 20's frames, even on the same hardware. Traffic between VLANs has to go through a router or Layer 3 switch. Trunk links (using 802.1Q tags) carry multiple VLANs between switches.

The isolation is enforced by the switch's configuration, not by physical separation — which is exactly what VLAN attacks try to subvert.

Why it matters for CEH: VLAN hopping (via switch spoofing or double-tagging 802.1Q frames) lets an attacker send traffic into a VLAN they shouldn't reach, defeating the segmentation defenders rely on to contain a breach.
Quick check

VLANs are often used to separate a guest network from an internal one. What does a VLAN hopping attack let an attacker do to that design?

Answer: Reach the internal VLAN from the guest VLAN — bypassing the segmentation that was supposed to keep guests isolated from internal systems.
