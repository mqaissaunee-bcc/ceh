Corrections for the “Hacking Web Servers” video

Read this after you watch the video. The video gets the big ideas right, but a few details are wrong and some topics are missing. Where the video and Module 13 disagree, go with the module.

Corrections

These points in the video are wrong or misleading.

The opening picture shows the wrong attacks

The video says

The title graphic surrounds the server with SQL injection, cross-site scripting and broken access control.

What’s correct

Those attack the application, and you will study them in Modules 14 and 15. This module is about the server: Apache, Nginx, IIS and their configuration. The narration gets this right at 0:47.

Read more: Overview → “Attacking the platform, not the app”

5:22

How encoded traversal slips past a filter

The video says

A web application firewall lets the encoded payload (such as %c0%af) through, and then the operating system decodes it into a slash.

What’s correct

The filter that was fooled was the web server’s own path check. The module says this trick “historically defeated IIS’s path validation.” A WAF is a defense that blocks traversal sequences. Also know %2e (an encoded dot) alongside %2f (an encoded slash).

Read more: Common Attacks → “Directory traversal”

6:04

The 2021 Apache traversal flaw

The video says

Attackers read a configuration file, pulled out credentials, and used those to get remote code execution. The video does not give the flaw’s ID.

What’s correct

The flaw is CVE-2021-41773, in Apache 2.4.49. The traversal bug itself also allowed remote code execution, with no stolen credentials involved, and it was exploited within a day of disclosure. Learn the CVE number.

Read more: Common Attacks → “Directory traversal”

9:40 and 10:17

Patching: the 24-hour window and how to prioritize

The video says

Major flaws “like Log4Shell” reach mass exploitation in 24 hours, and CISA’s KEV list is “the definitive triage tool.”

What’s correct

The module’s two examples are the Apache path traversal (CVE-2021-41773) and Log4Shell (CVE-2021-44228, exploited against Apache Tomcat). Patch the same day if a flaw allows remote code execution, or is on the KEV list, or has a high EPSS score. If you cannot patch yet, buy time: disable the vulnerable module, add a WAF rule, or put a proxy in front.

Read more: Countermeasures → “Patch management”

Access, denial and defacement attacks

Four server attacks never come up in the video:

  • Credential attacks: brute-forcing SSH, FTP or admin logins, for example with Hydra.
  • DoS/DDoS: flooding the server, including HTTP/2 resource-exhaustion flaws.
  • Website defacement: changing the site’s content, which shows the attacker gained write access.
  • Man-in-the-middle: intercepting traffic, the reason TLS everywhere matters.

Read: Common Attacks → “Access, denial, and defacement”

HTTP response splitting

The video names it but only explains cache poisoning. In response splitting, unvalidated input is reflected into a response header, so the server splits one response into two and the attacker controls the second. Example: Apache CVE-2023-38709. Both attacks are stopped by strict input validation and careful cache configuration.

Read: Common Attacks → “Protocol and caching attacks”

The parts of a web server, and the three tiers

A web server has six parts, and each can be attacked: core server software, modules and extensions, configuration, document root, TLS/SSL components, and the connection to backend servers. A site has three tiers: web server (this module), application (Module 14) and database (Module 15).

Read: Architecture → “What a web server actually does” and “Where the server meets the application”

How fingerprinting is actually done

Fingerprinting is also called banner grabbing: the HTTP Server header often names the software and version. Know nmap -sV, the Nmap scripts http-server-header, http-enum and http-methods, and curl -I. Tools the video skips: Netcraft and Wappalyzer (passive fingerprinting), dirb and dirbuster, and OpenVAS.

Read: Attack Methodology → “Step 1” and Tools → “Fingerprinting and discovery”

The rest of the hardening checklist

Beyond what the video lists: remove default certificates, sample applications and test pages; turn off directory listing; hide the Server banner; add security headers (HSTS, Content-Security-Policy, X-Content-Type-Options); and restrict file permissions. NIST SP 800-44 is a second standard alongside the CIS Benchmarks. For directory traversal, the defense is input validation that rejects traversal sequences and canonicalizes paths.

Read: Countermeasures → “Hardening”
