Overview — what this lab is really teaching

An intrusion detection system watches the network for patterns that look like attacks. This lab tries to slip a scan past one — with packet fragmentation, decoys, and a spoofed MAC — while a real IDS watches, so you can see exactly what each trick does and doesn't hide. It's the hands-on side of Module 12: Evading IDS, Firewalls, and Honeypots.

The honest, exam-relevant lesson is where this lands in 2026: a modern IDS reassembles fragments, correlates sources, and looks at behavior, so most of these classic evasions now get caught anyway. You learn them to understand the cat-and-mouse — and to appreciate why defense moved beyond simple signatures.

You scan from Kali while the pod's Security Onion sensor (running Snort/Suricata-style detection) watches the wire. The whole point of the lab is the feedback loop: run a scan, then go read the IDS to see whether — and how — it fired.

Command walkthrough

Read this before you copy anything

The source PDF uses en-dashes on some flags, and writes -PN and -spoof-mac — the correct current forms are -Pn and --spoof-mac. The copy buttons here emit the clean, correct options.

Step 1 — Establish a baseline

1 A normal scan, so you know what "loud" looks like

Run an ordinary Nmap scan first and check Security Onion. It will light up with scan alerts — this is your control. Every evasion below is measured against how much it reduces these alerts.

📸 Screenshot for your report

Capture the IDS alerts triggered by the baseline (un-evaded) scan.

Step 2 — Fragmentation

2 Split the packets

root@kali:~# nmap -f 192.168.0.30

-f breaks the scan's packets into tiny fragments, betting that a signature engine inspecting one packet at a time won't recognize the attack spread across several. The classic counter — and what Security Onion does — is to reassemble the fragments before matching, which is why this often still alerts.

Step 3 — Decoys

3 Hide in a crowd

root@kali:~# nmap -D 192.168.9.20,192.168.9.30,192.168.9.40 192.168.0.30

-D makes the scan appear to come from several source addresses at once — the decoys — so your real IP is buried among them in the logs. It doesn't stop detection; it muddies attribution, forcing the analyst to work out which source was real.

📸 Screenshot for your report

Capture the IDS showing the scan appearing to come from multiple sources (the decoys alongside your real one).

Step 4 — Spoofed MAC

4 Change your layer-2 identity

root@kali:~# nmap -sT -Pn --spoof-mac 0 192.168.0.30

--spoof-mac 0 randomizes your hardware address (0 = a random vendor); -sT is a connect scan and -Pn skips host discovery. Spoofing the MAC changes how you look on the local segment, but it only works on that segment and does nothing about the higher-layer patterns the IDS keys on.

The defender's view

This lab is really an argument for layered detection

Each evasion targets one weakness of naive signature matching. The modern answer is not a better signature but more layers.

  • Reassembly & normalization — the IDS/IPS rebuilds fragmented and oddly-encoded traffic before matching, defeating fragmentation and obfuscation.
  • Anomaly / behavior detection — flag the pattern of a scan (many ports, many hosts, fast) regardless of source or encoding.
  • Correlation — tie decoyed sources together and across sensors so one real actor stands out.
  • Defense in depth — host logs, EDR, and firewall data corroborate what the network sensor sees.
  • Honeypots — deliberately attractive decoy systems that catch scanners and reveal their methods.

Check yourself

1. What does -f try to achieve, and what defeats it?

It fragments packets so a single-packet signature engine misses the attack. A modern IDS reassembles the fragments before matching, so it often detects it anyway.

2. A decoy scan doesn't stop detection — so what does it actually accomplish?

It obscures attribution — your real source is hidden among decoys in the logs, forcing an analyst to figure out which one was genuine.

3. Why does spoofing your MAC do little against the IDS?

A MAC only matters on the local segment; it doesn't change the higher-layer scan patterns the IDS keys on, and it breaks the return path for replies.

4. Which detection approach catches a scan regardless of fragmentation or encoding?

Anomaly/behavior detection — it flags the behavioral pattern of scanning (many ports/hosts, high rate) rather than a specific packet signature.

Cheat sheet

Evasion flags

  • nmap -f TARGET — fragment
  • nmap -D d1,d2,ME TARGET — decoys
  • nmap --spoof-mac 0 TARGET
  • nmap -T0 / -T1 — slow
  • --data-length N · -g 53

Why it's caught

  • Reassembly + normalization
  • Anomaly / behavior detection
  • Source correlation across sensors
  • Defense in depth (host + net + EDR)
  • Honeypots
