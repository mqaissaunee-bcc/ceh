Overview — what this lab is really teaching

Labs 02–04 taught individual tools. This one teaches the order you use them in — the repeatable scanning methodology that turns a blank network range into a ranked list of targets: discover live hosts → map ports and services → grab banners → probe and scan → check for web vulnerabilities. It's the practical heart of Module 3: Scanning Networks.

You'll touch several tools on purpose, because methodology is tool-agnostic. Two are Windows GUIs (Advanced IP Scanner, Angry IP Scanner) for quick live-host sweeps; the rest — Nmap, hping3, and Nikto — do the real work from Kali. The skill to carry away is the sequence, not any one command.

The environment you're working in

You drive Nmap, hping3, and Nikto from Kali against the pod's two subnets (192.168.0.0/24 and 192.168.9.0/24). The GUI scanners run on the Windows VM. Along the way you'll save scan output to files on the Desktop and feed them from one tool to the next — which is exactly how real assessments chain together.

Command walkthrough

Read this before you copy anything

Two source-PDF traps here: the Nmap script option prints as -script=banner (the correct, unambiguous form is --script=banner), and the awk / grep pipelines use curly quotes that the shell rejects. The copy buttons emit clean characters.

Step 1 — Discover live hosts

1 Host discovery with traceroute

root@kali:~# sudo nmap -sn -Pn --traceroute 192.168.0.2,20,30,100,254

-sn says "discover hosts, don't port-scan"; -Pn says "assume they're up, skip the ping"; --traceroute maps the path to each. The target is a comma-separated list of last octets — a quick way to probe several hosts at once. The GUI scanners (Advanced IP Scanner, Angry IP Scanner) do the same live-host sweep with a point-and-click interface.

Step 2 — Map ports and services

2 Scan specific ports across subnets

root@kali:~# sudo nmap -p80,53,22 192.168.0.0/24 192.168.9.0/24

Rather than scan every port on every host, you target the ports that matter (web, DNS, SSH) across whole subnets. Nmap happily takes multiple ranges at once.

3 Grab service banners

root@kali:~# sudo nmap -sV --script=banner 192.168.9.1

-sV identifies the service and version; the banner NSE script pulls the text a service announces on connect. Versions and banners are what you'll later match against known vulnerabilities.

Step 3 — Build a target list from your results

4 Extract the live IPs into a file

root@kali:~# cat Desktop/list.txt | awk '/Up$/{print $2}' >> Desktop/targets.txt
root@kali:~# cat Desktop/targets.txt

This is the real-world move: take saved scan output, pull just the addresses that were Up with awk, and append them to a clean target list. Tools that take a -iL/-h host file can now run against exactly the live hosts.

Step 4 — Probe with hping3

5 TCP probes and a port sweep

root@kali:~# hping3 -c 3 192.168.0.20
root@kali:~# hping3 -S 192.168.0.20 -p 80 -c 5
root@kali:~# hping3 -q --scan 1-3000 -S 192.168.0.20 | grep -v 'Not res'

A quick count-limited probe, then a SYN probe to port 80, then a quiet SYN sweep of ports 1–3000 with the unresponsive ports filtered out by grep -v. (See Lab 04 for the full hping3 breakdown.)

Screenshot for your report

Capture the --scan 1-3000 results showing the open ports found on the target.

6 UDP packet crafting

root@kali:~# hping3 192.168.0.20 --udp --rand-source --data 500

--udp switches to UDP, --data 500 adds a 500-byte payload, and --rand-source forges a random source address on every packet.

Know what this one is

--rand-source with no count is a spoofed flood — you can't receive replies, and on a real network it's a denial-of-service pattern. It's safe in the isolated pod; never aim it at anything you don't own. Stop it with Ctrl-C.

Step 5 — Check for web vulnerabilities

7 Scan web hosts with Nikto

root@kali:~# nikto -h Desktop/targets.txt

nikto -h runs a web-server vulnerability scan against every host in your list — outdated software, dangerous files, misconfigurations, missing headers. It closes the methodology loop: discovery fed a target list, and the target list fed the vuln scan.

The defender's view

A methodical attacker leaves a methodical trail

The orderly sweep that makes scanning efficient also makes it detectable — discovery, then ports, then versions, then a web scan, all from one source.

  • Detect the sequence — IDS/IPS and firewall scan-detection flag the burst of discovery and port probes; Nikto's requests are loud and signature-heavy.
  • Shrink the surface — every closed port, removed service, and patched banner is one less thing the methodology can find.
  • Don't leak versions — suppress or genericize banners so -sV and --script=banner learn less.
  • Rate-limit and anti-spoof — frustrate hping3's sweeps and drop the forged sources of --rand-source.

CEH v13 exam relevance

The methodology that ties Module 3: Scanning Networks together. High-yield facts:

  • The scanning sequence: host discovery → port scan → service/version → OS → vulnerability.
  • Host discovery vs. port scanning — -sn vs. a port scan, and when to use -Pn.
  • Banner grabbing as a fingerprinting technique.
  • Nikto as the go-to web-server vulnerability scanner.
  • Chaining tools — feeding one tool's output into the next via host-list files.

Check yourself

1. What does -sn do, and how is it different from -Pn?

-sn does host discovery only (no port scan). -Pn skips host discovery entirely and treats hosts as up. They're often combined to force a scan of hosts that don't answer pings.

2. Put these in order: service/version detection, host discovery, web vulnerability scan, port scan.

Host discovery → port scan → service/version detection → web vulnerability scan. You narrow from "what's alive" to "what's exploitable."

3. What makes the hping3 ... --udp --rand-source command dangerous on a real network?

It forges random source addresses and floods UDP with no count — a denial-of-service / spoofing pattern. Only run it in an isolated lab you own.

4. Why grab banners before looking for vulnerabilities?

The service and version in a banner are what you match against known-vulnerability databases to decide what's worth attacking.

Cheat sheet

Nmap methodology

  • nmap -sn CIDR — live hosts
  • nmap -sn -Pn --traceroute IPs
  • nmap -p 80,53,22 CIDR — targeted ports
  • nmap -sV --script=banner IP
  • ... | awk '/Up$/{print $2}' >> targets.txt

Probe & web-scan

  • hping3 -S IP -p 80 -c 5
  • hping3 -q --scan 1-3000 -S IP
  • hping3 IP --udp --data 500 -c N
  • nikto -h targets.txt
  • nikto -h URL -ssl -o report.html
