Overview — what this lab is really teaching

Scanning told you a port is open. Enumeration is where you actively connect to that service and ask it questions: what users exist? what shares? what's the password policy? what's the domain structure? It's the step that turns "port 445 is open" into "here are the usernames I'll attack" — Module 4: Enumeration.

The concept that ties it together is the null session — connecting with no credentials and still being handed a surprising amount of information. You'll see it firsthand with enum4linux against a target that allows it.

The environment you're working in

From Kali you enumerate hosts on the 192.168.0.0/24 network, with the deeper SMB/LDAP work aimed at the domain machine at 192.168.0.20. A couple of enumeration tools (SuperScan, NetBIOS Enumerator) run on the Windows VM, but the heavy lifting is nmap and enum4linux from the command line.

Command walkthrough

Task 1 — Find hosts and services with Nmap

1 Sweep for live hosts

root@kali:~# nmap -sP 192.168.0.0/24

A ping sweep to list the active hosts on the subnet before you dig into any one of them.

Currency note

-sP is the old name for the ping sweep and is now -sn. Nmap still accepts -sP for compatibility, but learn -sn — that's what you'll see today and on the exam.

2 Identify services and the OS

root@kali:~# nmap -sSV -O 192.168.0.30

-sSV is two flags in one: -sS (SYN scan) plus -sV (service/version detection). Add -O for OS detection and you get, in one command, the open ports, the software and versions behind them, and the operating system. That service-and-version list is the menu you enumerate from.

📸 Screenshot for your report

Capture the -sSV -O output showing the services, their versions, and the OS guess.

Task 2 — Enumerate SMB & LDAP with enum4linux

3 Pull everything the target will give

root@kali:~# enum4linux -a -v -l 192.168.0.20

This is the centerpiece. -a runs "all" of enum4linux's checks, -v is verbose, and -l adds LDAP enumeration. Against a target that permits a null session, it returns users, groups, shares, the password policy, RID-cycled account names, OS details, and LDAP/domain information — often with no credentials at all.

📸 Screenshot for your report

Capture a section of the enum4linux output — the enumerated users or shares, and the line confirming the null session succeeded.

What "RID cycling" means in that output

Every Windows account has a Relative Identifier (RID). By walking RIDs in sequence, enum4linux coaxes the system into naming account after account — a classic way to build a username list for later password attacks.

Task 3 — The GUI equivalents

4 SuperScan & NetBIOS Enumerator (Windows)

On the Windows VM, SuperScan performs port scanning plus host/NetBIOS enumeration, and NetBIOS Enumerator pulls NetBIOS names, shares, and domain data through a GUI. Same information as the SMB/NetBIOS parts of enum4linux — useful to see the concept from a Windows attacker's perspective.

The defender's view

Enumeration thrives on defaults

Almost everything enum4linux pulls back exists because something was left open: null sessions allowed, default SNMP community strings, anonymous LDAP binds.

  • Disable null sessions and anonymous access — restrict SMB/RPC so unauthenticated users learn nothing (RestrictAnonymous and its modern equivalents).
  • Change SNMP community strings off public/private, or move to SNMPv3 with authentication.
  • Lock down LDAP — require authenticated binds; don't expose the directory anonymously.
  • Retire NetBIOS/SMBv1 and segment file services so they aren't reachable from everywhere.
  • Watch for it — bursts of RID lookups and share enumeration are detectable patterns.

Hands-on side of Module 4: Enumeration. High-yield facts:

Check yourself

1. In one sentence, how is enumeration different from scanning?

Scanning finds open ports and services; enumeration actively connects to those services to extract specifics — users, shares, policies, directory data.

2. What is a null session, and why does it matter to an attacker?

A connection made with no username or password that still returns information (users, shares, policy). It lets an attacker enumerate a host before ever obtaining credentials.

3. What does the -sSV in nmap -sSV -O actually combine?

A SYN scan (-sS) and service/version detection (-sV), with -O adding OS detection.

4. enum4linux comes back nearly empty against a host. What does that most likely tell you?

Null sessions/anonymous access are disabled — the host is configured securely. You'd need valid credentials to enumerate further.

Cheat sheet

Discover & identify

  • nmap -sn CIDR — live hosts (was -sP)
  • nmap -sSV -O IP — services + OS
  • nmap --script smb-enum-shares,smb-enum-users IP

Enumerate

  • enum4linux -a -v -l IP — all/SMB/LDAP
  • smbclient -L //IP — shares
  • snmpwalk -v2c -c public IP
  • ldapsearch -x -H ldap://IP -b "dc=…"
  • rpcclient -U "" IP — null session
