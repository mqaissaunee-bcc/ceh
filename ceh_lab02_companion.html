Overview — what this lab is really teaching

Every tool in this course — Nmap, Hping, the sniffers, the spoofers — is ultimately sending and receiving packets. Scapy lets you build those packets by hand, one field at a time, inside an interactive Python session. Once you've assembled a SYN packet yourself, Nmap's -sS stops being magic.

The mental model is the heart of it: a packet is a stack of layers — Ethernet, then IP, then TCP, then your payload — and in Scapy you stack them with the / operator. You build it, send it, and read what comes back.

The environment you're working in

You run Scapy on Kali (as root — crafting raw packets needs it) and send toward the OWASP BWA host at 192.168.68.12. You'll open Wireshark alongside so you can watch the packets you craft actually leave the machine — the "oh, that's what that does" moment of the whole lab.

Command walkthrough

Task 1 — Explore and build a packet

1 Launch Scapy and look around

root@kali:~# scapy
>>> ls()
>>> lsc()

scapy drops you into a Python prompt with networking superpowers. ls() lists every protocol layer Scapy knows; lsc() lists the commands (send, sniff, and friends). Think of these two as your table of contents.

2 Create an IP layer and inspect its fields

>>> ip=IP(ttl=10)
>>> ip
>>> ip.dst
>>> ip.src

You've made an IP packet object and set its time-to-live to 10. Typing the variable shows a summary; ip.dst and ip.src read individual fields. Unset fields show sensible defaults.

3 Set, delete, and re-read fields

>>> ip.dst="192.168.9.1"
>>> ip.src="192.168.9.2"
>>> del(ip.ttl)
>>> ip.ttl

Fields are just attributes you can assign. del(ip.ttl) removes your override and lets the field fall back to its default — a neat way to see which values you've actually pinned versus which Scapy fills in.

4 Stack a TCP layer

>>> ip/TCP()
>>> tcp=TCP(sport=1025, dport=80)
>>> (tcp/ip).show()

The / operator stacks layers: IP()/TCP() is a TCP segment riding on an IP packet. Here you build a TCP layer with a source port of 1025 and a destination of 80, then (tcp/ip).show() prints the full stacked packet field by field so you can confirm the TCP header sits on top of the IP header.

>>> Ether()/ip

Prepending Ether() adds a layer-2 Ethernet frame beneath the IP packet — a reminder that a real frame on the wire is layers all the way down (Ethernet → IP → TCP → payload). Anything with an Ether() layer is sent with the layer-2 functions (srp/sendp), not sr1.

Task 2 — Send packets and read the replies

5 Watch the wire, then send

root@kali:~# wireshark
>>> packet=sr1(IP(dst="192.168.68.12")/ICMP()/"XXXXXXXXXXX")
>>> packet

In Wireshark, select the eth0 interface and press Ctrl+E to start capturing before you send. sr1() means send one packet and return the first reply. This one is an ICMP echo (a ping) with a custom payload of X's — look for it in Wireshark. Inspecting packet shows the response that came back.

Screenshot for your report

Capture the Wireshark row for your crafted ICMP packet — the one carrying the XXXXXXXXXXX payload. It proves the packet you built actually left the machine.

6 Craft a SYN and read the handshake

>>> packet=sr1(IP(dst="192.168.68.12")/TCP(dport=80,flags="S"))

This is a port scan in miniature: a single SYN to port 80. If the reply carries flags SA (SYN/ACK) the port is open; a RA (RST/ACK) means closed. You just did by hand what nmap -sS automates thousands of times.

Inspect it properly

packet.show() prints every field of the response, layer by layer — the best way to confirm which flags came back.

Screenshot for your report

Capture the sr1 SYN reply (run packet.show()) with the TCP flags visible — SA means the port is open.

The defender's view

Why defenders should care about packet crafting

Hand-crafted packets are how attackers spoof sources, evade naive filters, and fuzz services. The same skill powers blue-team detection engineering.

  • Anti-spoofing — ingress/egress filtering (BCP 38) and uRPF drop packets whose source address can't be real.
  • Stateful inspection — firewalls that track connection state reject lone, out-of-context packets (a bare ACK, an orphan FIN).
  • Anomaly detection — IDS/IPS flag malformed or impossible flag combinations that crafted packets often carry.
  • Use it defensively — Scapy is a first-rate tool for reproducing an attack to test whether your own detections fire.

CEH v13 exam relevance

Supports Module 3 (Scanning) and underpins sniffing and spoofing later. High-yield facts:

  • The TCP flags and the three-way handshake at the packet level: SYN, SYN/ACK, ACK; RST on refusal.
  • Reading scan results from flags: SA = open, RA = closed, no reply = filtered.
  • The layered model — which protocol lives at which layer, and what "packet crafting" means.
  • Packet crafting as the basis for custom scans, firewalk testing, and spoofing.

Check yourself

1. What does the / operator do in IP()/TCP()/"data"?

It stacks protocol layers — an IP packet carrying a TCP segment carrying a raw payload. Scapy builds packets by composing layers this way.

2. A copied line throws SyntaxError. What's the most likely cause?

Curly "smart quotes" from the document instead of straight quotes. Retype the quotes.

3. You send a SYN with sr1 and the reply has flags SA. Open or closed?

Open — SA is SYN/ACK, the server agreeing to the handshake. A RST/ACK (RA) would mean closed.

4. Why does sr1() sometimes appear to hang, and how do you prevent it?

It waits for a reply that may never come (filtered port or silent host). Pass a timeout= value.

Cheat sheet

Build

  • scapy — start the session
  • ls() / lsc() — layers / commands
  • p = IP(dst="x")/TCP(dport=80,flags="S")
  • p.dst, p.ttl=10, del(p.ttl)
  • p.show() — dump all fields

Send & capture

  • sr1(p, timeout=2) — one reply
  • send(p) — fire and forget (L3)
  • srp(p) / sendp(p) — layer 2
  • sniff(count=10) — capture
  • Flags: SA=open, RA=closed
